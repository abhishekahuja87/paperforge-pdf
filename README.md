# MyDailyUtils

A growing collection of free, browser-based everyday tools: finance and tax calculators, date, unit and percentage tools, text and password utilities, image and PDF tools, data formatters, presentations, and billing. PDF is one category among several, not the focus of the site. The application is built with React, TypeScript, Vite, Tailwind CSS, and pnpm.

## Development

- `pnpm install` installs dependencies.
- `pnpm dev` starts the development server.
- `pnpm build` type-checks and builds the application.
- `pnpm lint` runs Oxlint.
- `pnpm preview` serves the production build locally.

## Architecture

- `src/App.tsx` defines the lazy-loaded routes and shared header and footer. A catch-all `*` route renders `src/pages/NotFoundPage.tsx` (localized, links to popular tools, and `noindex` through `PageMetadata`). Static hosts still answer unknown URLs with the SPA shell, so the `noindex` tag is what keeps those URLs out of search results.
- `src/components/common/ProtectedPdfGate.tsx` provides `useProtectedPdf()`. Single-file PDF tools (split, rotate, compress, delete pages, crop, n-up, page numbers, watermark, organize, flatten, PDF to images) and Merge call `prepare(file)` on every upload. A password-protected PDF opens a password dialog and continues with an unlocked copy rebuilt from page images (via `lib/pdf/unlock.ts`); the original is never changed. Extract text, Inspect, Sanitize, Protect and Unlock keep their own handling, and Document Studio keeps its own dialog.
- Shareable links: `src/lib/shareState.tsx` (`ShareProvider`, `useShared`) and `src/components/common/ShareLinkBar.tsx`. `NumberField`, `SelectField`, `DateField` and `ChoiceButtons` register their value under a key made from their label (override with `shareKey` when a label changes with a mode), and read it back from the address on first load. `FinanceCalculatorPage` and `UtilityPage` wrap the calculator and show the bar; `UtilityPage` lists the shareable kinds in `SHAREABLE` (text, random and invoice tools are left out on purpose). Only numbers, dates and choices go in a link. Renaming a field label changes its key and breaks old links.
- Packs (groups of tools for one kind of person) keep everything in their own files, so a new pack never edits a big shared file:
  - config: `src/config/packs/<pack>.ts` lists the pack's tools with `definePackTool` (id, screen `kind`, `guideKey`, category, icon, tier, keywords, `shareable`); `src/config/packs/index.ts` collects the packs, and `src/config/tools.ts` appends them to `TOOLS`.
  - text: `src/locales/packs/<pack>.en.json` holds `toolCatalog`, `guideSteps`, `pageGuides` and `toolArticles` for the pack's tools; `src/locales/english.ts` merges every pack into the English text (import `en` from there when you need catalogue, guide or article copy). Titles and descriptions in the config come from this file.
  - screens: `src/components/tools/<pack>/` with a `registry.ts` of lazy screens; `src/components/tools/packRegistry.ts` merges the registries.
  - page and routes: `src/pages/PackToolPage.tsx` renders every pack tool (heading, guide, FAQ, optional share bar) and `src/App.tsx` creates one route per pack tool from the config. The static page generator and sitemap read the same config. `public/sitemap.xml` is only a fallback.
  - To add a pack: write the locale file, the config file and the screens, then add one line each in `locales/english.ts`, `config/packs/index.ts` and `components/tools/packRegistry.ts`.
- Careers pack (`careers`): Resume Builder (`lib/careers/resume.ts`, a wording and completeness checklist, print to PDF, optional local save, data file export), Notice Period Calculator (`lib/careers/notice.ts`) and Upload File Checker (`lib/careers/fileCheck.ts`, `lib/pdf/probe.ts`).
- Students pack (`students`): GPA and CGPA Calculator (`lib/students/gpa.ts`), Final Grade Calculator (`lib/students/grades.ts`), Citation Generator (`lib/students/citation.ts`, APA, MLA, Chicago, Harvard; website, book, journal) and Study Planner (`lib/students/planner.ts`). Text is in `locales/packs/students.en.json`, tool entries in `config/packs/students.ts`, screens in `components/tools/students`.
- `src/pages/UtilityPage.tsx` loads each calculator/utility component on demand (one `lazy()` per tool), so opening one utility does not download the others. Known remaining cost: `src/locales/en.json` (~220 KB, mostly guide and article text) is imported eagerly by `src/i18n.ts` so server-side prerendering and first paint have English text; splitting it is a possible future optimisation.
- `src/pages/` connects route-specific headings and guides to tool components.
- The unlisted `/ac1` catalog trial offers designs for 4, 6, 9 or 12 products, including arched, asymmetric, side-panel and list layouts. Its English-only editor uses local sample photos, in-memory text and image edits (uploaded photos fit inside their frames by default, with per-photo zoom and vertical positioning), and browser-side PNG export for A4 and Instagram sizes. Changes are lost on reload.
- Tool categories (`ToolCategory` in `src/config/tools.ts`): `pdf`, `media`, `finance`, `everyday`, `text`, `dev`, `display`, `business`. The homepage "Most used" row deliberately mixes categories (PDF, image, tax, loan and age tools); keep it mixed as the catalog grows. Footer columns, `HOME_CATEGORY_ORDER`, category copy (`categories` in `en.json`) and the static page generator all need an entry when a category is added.
- `src/components/tools/` contains the interactive tools; `src/lib/pdf/`, `src/lib/media/`, `src/lib/documentStudio/`, `src/lib/display/`, and `src/lib/pos/` contain domain-specific processing and helpers.
- `src/components/layout/ToolLayout.tsx`, `src/components/common/ToolGuide.tsx`, and `src/components/common/FileDropZone.tsx` provide the shared tool-page presentation and file selection patterns. Use the `wide` layout for workspaces that need additional room.
- `src/config/tools.ts` defines the tool catalog and categories. Every tool has a `tier`: `popular` (compact "Most used" tiles), `workspace` (slim "Workspaces" cards using the `featuredTools` copy), `more` (always-expanded "More tools" groups by category) or `advanced` (footer only). Ordering, tier helpers and search are in `src/lib/homePageVariants.ts`; search covers every tier so footer-only tools stay findable. Homepage components live in `src/components/home/`. The footer (`src/components/layout/Footer.tsx`) lists every available tool in category columns plus a Company column.
- `src/components/layout/InfoPageLayout.tsx` provides the shared informational-page presentation. `PageMetadata` manages route metadata and canonical URLs.
- The Image Resizer (`src/components/tools/ImageResizer.tsx`, logic in `src/lib/media/resizeToTarget.ts`) re-encodes images as JPG under a size limit in KB by searching for the highest quality that fits, scaling down in steps only when no exact pixel size is set. `/image-resizer` plus the landing pages `/resize-image-to-20kb|50kb|100kb|200kb` share one component through `src/pages/ImageResizerPage.tsx`; each landing page has its own `pageGuides` and `toolArticles` copy so the pages are not duplicates. These presets are `advanced` (footer and search only).
- `scripts/prerender-shell.mjs` also writes `dist/sitemap.xml` from `getShellPages()`, so the deployed sitemap always matches the real pages. `public/sitemap.xml` is only the fallback if static generation fails, so keep it in sync when adding a page. `AdBanner` requests an ad only when its slot is about to scroll into view. The unfinished catalog pages (`/ac1`, `/ac1/edit`, `/catalog-templates`) are `noindex` and not linked anywhere; the header menu lists homepage tiers only (footer-only `advanced` tools appear in the footer and search).
- More calculators (batch 3): gratuity, lumpsum and inflation (`finance`; lumpsum and inflation are `advanced`), BMI and bill splitter (`everyday`; bill splitter is `advanced`). Maths is in `src/lib/utilities/more.ts`. BMI offers Asian (23/25) and WHO (25/30) cut-offs and carries a not-medical-advice note; the gratuity ₹20 lakh tax-free limit and 15/26 formula should be rechecked if the law changes. About, Privacy and Terms now prerender a short summary section in `shellData.ts` so crawlers see body text; keep it consistent with the real pages and bump the 'Last updated' date when those pages change.
- Depth pass on the utilities and calculators: shared `SplitBar` (principal versus interest) and `ResultActions` (copy summary, print) live in `src/components/finance/ui.tsx`; tables, extra modes (add/subtract dates, reverse discount, reverse percentage), text clean-up, PIN and bulk passwords, BMR calories and unit tables are in the individual components. Helpers: `addMonths`, `addDays`, `zodiacSign` (`dates.ts`), `cleanupText`, `textExtras` (`text.ts`), `generatePin`, `crackTime` (`password.ts`), `dailyCalories`, `yearlyGrowth` (`more.ts`). Page copy (FAQs, articles) in `en.json` must describe these extras; update both together. The platform length limits in the word counter are typical published values and may change.
- Form photo tools: the Image Resizer now has quick presets (`src/lib/media/photoPresets.ts`: passport 35 × 45 mm, 2 × 2 inch, exam photo 200 × 230 px, signature 140 × 60 px, small profile), exact size in px, mm, cm or inches with a DPI (`toPixels`), and a background colour. `ImageResizerPage` takes an optional `defaultPreset`; the landing pages `/passport-photo-resizer`, `/signature-resizer`, `/exam-photo-resizer` and `/resize-image-to-30kb` are `advanced` and have their own `pageGuides`/`toolArticles` copy. Preset sizes are common requests, not official rules for any exam; page copy tells users to follow their own form, and any copy that names a size must keep saying so.
- Accessibility conventions: modal dialogs use `useDialog` (`src/lib/useDialog.ts`): Escape closes, Tab stays inside, focus moves in and returns to the opener, the page behind does not scroll; put its ref and `tabIndex={-1}` on the `role="dialog"` element. Every input needs a wrapping `<label>`, a `<label htmlFor>` with a matching `id`, or an `aria-label`; icon-only buttons need `aria-label`; toggle buttons need `aria-pressed`; icon buttons should be at least 40 px (`min-h-10 min-w-10`).
- GST Invoice Generator (`/gst-invoice-generator`, `finance`, `more`): maths and the GSTIN format/check-character validator are in `src/lib/gst/invoice.ts`, the form and printable preview in `src/components/tools/finance/GstInvoiceGenerator.tsx` (printing uses a `@media print` rule that shows only `#gst-invoice-print`; the user saves as PDF from the print dialog). Intra-state (same seller and buyer state) charges CGST + SGST, otherwise IGST; a 'bill of supply' mode charges no tax. Seller details, notes and bank details are stored in localStorage only when the user ticks 'Remember my business details' (key `mdu-gst-seller`); Privacy and copy must keep saying this. It does not produce e-invoices (IRN/QR) or verify registration; keep that disclaimer. State codes and rate list are in the same lib file; review them when the GST Council changes rates.
- Batch 4: EPF calculator (`finance`, EPF/EPS split and interest rules documented in `projectEpf` in `src/lib/utilities/dev.ts`; the default 8.25% rate and the ₹15,000 EPS wage cap must be rechecked when the government changes them), time zone converter (`everyday`, uses `Intl` and the browser's time zone data), lorem ipsum generator (`text`), colour converter with WCAG contrast, UUID v4 generator, Unix timestamp converter and URL encoder/decoder (`dev`). Shared logic is in `src/lib/utilities/dev.ts`.
- Everyday utilities: simple/compound interest, RD and CAGR (`finance`), age, date difference, percentage, discount and unit converter (`everyday` category), word counter, case converter and number to words (`text`), and a password generator (`dev`). Logic in `src/lib/utilities/`, components in `src/components/tools/utilities/` (plus three in `tools/finance/`), mapped to routes by `src/pages/UtilityPage.tsx`. The password generator uses `crypto.getRandomValues` only.
- Finance & Tax calculators (`finance` category): income tax old vs new, salary CTC to in-hand, HRA, EMI, SIP, FD, PPF and GST. Maths lives in `src/lib/finance/` (`tax.ts` holds the FY 2026-27 slabs, rebate, surcharge and cess constants and must be reviewed every Budget; `calculators.ts` the rest), shared inputs and result blocks in `src/components/finance/ui.tsx`, one component per calculator in `src/components/tools/finance/`, and `src/pages/FinanceCalculatorPage.tsx` maps each route to its calculator and `pageGuides` entry. HRA, FD and PPF are `advanced` (footer and search only). The PPF default rate (7.1%) is the rate announced for Oct-Dec 2026; update it when the government revises it.
- How-to guides live in `src/content/guides.ts` (26 guides, plain data, English only) and render at `/guides` and `/guides/<slug>` through `GuidesPage`/`GuidePage`; the static page generator and its sitemap read the same list. Every claim about a tool in a guide must match the tool's code. Tool ids in `tools` become "Try it" links.
- Hosting (AWS Amplify): the generator writes both `dist/<route>/index.html` and `dist/<route>.html` so `/route` is served without a redirect. The Amplify rewrite rule must NOT be the usual single-page-app 200 rewrite, because that sends every address to the empty app page and hides the pre-built pages. Use one rule instead: source `/<*>`, target `/index.html`, type `404-200`, so only addresses with no pre-built page fall back to the app. Non-English locale files are loaded on demand by `changeAppLanguage` in `src/i18n.ts` and are not part of the main bundle.
- Analytics: `index.html` loads Google Tag Manager (container `GTM-T22RPG7D`) with consent defaulting to denied in the EEA, UK and Switzerland. Tags themselves (the Google Analytics 4 tag) are configured inside Tag Manager, not in code. The Privacy Policy (section 5) must stay consistent with what runs there.
- `src/components/common/ToolArticle.tsx` renders a longer written explanation under a tool; `ToolLayout` looks it up in the `toolArticles` resource by route path (for example `merge-pdf`), and renders nothing when a tool has no entry. Article text is currently English only; other languages fall back to it through `fallbackLng`, so write new articles in `en.json` first and translate them before enabling another language. Articles must describe what the tool really does (read its code first), including limits.
- Search and sharing metadata: tool page titles are `<tool name> <siteConfig.toolTitleSuffix> | MyDailyUtils` (built in `ToolLayout` and in `src/prerender/shellData.ts`, so keep both in step). `src/lib/structuredData.ts` builds the schema.org JSON-LD (WebApplication and BreadcrumbList for tools, WebSite for the home page); `PageMetadata` writes it as `script#page-jsonld` and the static pages use the same id, so the app replaces rather than duplicates it. `public/og-image.png` (1200x630) is the shared social preview referenced from `index.html`; regenerate it if the brand changes. `public/sitemap.xml` is only the fallback copy; the build writes the real one.
- `pnpm build` ends with `build:static` (`scripts/prerender-shell.mjs` with `src/prerender/shellData.ts`), which writes `dist/<route>/index.html` for every route with its own title, description, canonical tag and a plain-HTML copy of the page text, including `toolArticles`, steps and FAQs. React replaces that text when the app loads. The step now fails the build if it breaks (so a broken deploy never goes live without pre-built pages); the log line `prerender-shell: wrote N static pages and sitemap.xml` confirms it ran. `ErrorBoundary` wraps the routes and reloads the page once after a failed script download following a new deploy.
- Publisher identity lives in `src/config/site.ts`: `location` (shown in the footer, About and Contact) and `contactEmail` (shown on About, Contact and Privacy only when it is not empty). Leave `contactEmail` empty until the mailbox exists. The brand name is used as the publisher; do not add personal details to the site. The Google consent message for the EEA, UK and Switzerland is configured in the AdSense account (Privacy & messaging), not in this repository.
- `src/i18n.ts` initializes i18next and react-i18next, persists the language choice locally, and loads one JSON file per language from `src/locales/`. Tool "How to use" steps, catalog copy, category copy, featured cards, shared navigation, and selected page headings, guides and controls have translations. Most tool controls, messages, FAQs, informational pages, and metadata still need to be moved into resources and translated. Shared guide steps use `guideSteps` keys matching route paths; Merge, Split, and Master Document Studio use their own existing resource groups. `usePageGuide` and `usePageFaqs` read migrated page copy from `pageGuides`; `usePageHeading` reads independently migrated headings from `pageHeadings`. The shared file drop zone defaults to the localized single-PDF prompt; other file prompts may still need translation. Keep resource keys and arrays consistent across languages and update guidance when its tool changes. The `merge`, `image`, and `categories` objects are also exposed as i18next namespaces. Do not remove the partial-translation notice until all visible and accessible text is covered and translations are reviewed. The language selector currently offers English only: `enabledLanguageCodes` in `src/i18n.ts` controls which languages visitors can choose (a saved choice for a hidden language falls back to English, and the selector is not rendered when only one language is enabled). The other locale files are kept and must still be updated with every new key; add a language's code to `enabledLanguageCodes` once it is complete and reviewed. `src/lib/localizedTool.ts` supplies catalog copy to navigation and search.
- The Display and POS page guides use `displayPage` and `posPage` resources; their workspaces still contain untranslated controls and messages. The Contact page uses `contactPage`, including its Web3Forms disclosure. About, Privacy and Terms are not yet translated. `InfoPageLayout` defaults content language to English until a page supplies its translated language.
- Master Document Studio and Document Digitization hide their guides while sources are present; Display Studio hides its guide while slides are present and retains its privacy note. Guides return when the workspace is cleared.
- The sample PDF generator uses `sampleControls` for its interface; its editable default document titles and generated sample content are still English. The sample, images-to-PDF, PDF inspector and JSON formatter page headings and FAQs use `pageGuides`. Their remaining tool controls and messages, and other tool-page FAQs and headings, are not all translated.
- Page-numbering, watermark, N-up, sanitize, inspect, protect, unlock, text extraction, PDF-to-image, flatten, organize, and Base64 page headings and FAQs are localized. Their interactive controls, result messages, and reports are not yet fully localized. The N-up, sanitize, and inspect information panels use `toolInfo`; keep their capability and security limitations accurate when updating them.
- `src/config/theme.json` contains the shared background, surface, shadow, and workshop overrides, which `src/main.tsx` exposes as CSS variables. Other Tailwind palette colors, static HTML and icon colors, and tool-specific design or export colors are not yet centralized. Preserve user-selected and generated document colors separately from website theme colors.
- `public/favicon.svg` supplies the browser icon and header mark.

## Processing and privacy

Supported file operations, calculators and text tools run in the browser; this does not mean that the entire site is offline. The site loads third-party advertising and may request PDF character maps from jsDelivr. The contact form separately sends its submitted details to Web3Forms. The privacy and terms pages describe these boundaries and must remain consistent with actual behavior. Language preferences and tool-visit counts use browser local storage. POS profiles and inventory can be explicitly saved, replaced, loaded, or deleted in IndexedDB via `src/lib/pos/profileStorage.ts`; bills and customer details are not saved there. Profile and bill JSON downloads remain the portable backup. Browser storage can be cleared or unavailable, so it is not a substitute for a backup.

Document digitization uses Tesseract.js with the English model. Vite serves and emits the worker, engine variants and language data from installed npm packages under `ocr-assets/`; they are downloaded from the application origin when needed. OCR runs on the rendered, edited pages after blackouts, and a text-only layer is added to the PDF. Separate output groups copies by source image into a ZIP. OCR is approximate and users should review the result. The digitization workspace does not offer password protection because the existing protection implementation rasterizes the PDF and removes searchable text. The reused Master Studio editor still has English-only controls.

When adding or changing a tool, keep routes, catalog entries, search, guide content, metadata, accessibility, translations, and relevant privacy disclosures consistent. Keep UI composition separate from reusable processing logic. Update this document when architecture or processing boundaries change.
