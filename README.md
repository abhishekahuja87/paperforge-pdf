# MyDailyUtils

A growing collection of free, browser-based everyday tools: finance and tax calculators, date, unit and percentage tools, text and password utilities, image and PDF tools, data formatters, presentations, and billing. PDF is one category among several, not the focus of the site. The application is built with React, TypeScript, Vite, Tailwind CSS, and pnpm.

## Development

- `pnpm install` installs dependencies.
- `pnpm dev` starts the development server.
- `pnpm build` type-checks and builds the application.
- `pnpm lint` runs Oxlint.
- `pnpm preview` serves the production build locally.

## Architecture

- `src/App.tsx` defines the lazy-loaded routes and shared header and footer. A catch-all `*` route renders `src/pages/NotFoundPage.tsx` (localized, links to popular tools, and `noindex` through `PageMetadata`). Static hosts still answer unknown URLs with the SPA shell, so the `noindex` tag is what keeps those URLs out of search results.
- `src/components/common/ProtectedPdfGate.tsx` provides `useProtectedPdf()`. Single-file PDF tools (split, rotate, compress, delete pages, crop, n-up, page numbers, watermark, organize, flatten, PDF to images) and Merge call `prepare(file)` on every upload. A password-protected PDF opens a password dialog and continues with an unlocked copy rebuilt from page images (via `lib/pdf/unlock.ts`); the original is never changed. Extract text, Inspect, Sanitize, Protect and Unlock keep their own handling, and Document Studio keeps its own dialog.
- Shareable links: `src/lib/shareState.tsx` (`ShareProvider`, `useShared`) and `src/components/common/ShareLinkBar.tsx`. `NumberField`, `SelectField`, `DateField` and `ChoiceButtons` register their value under a key made from their label (override with `shareKey` when a label changes with a mode), and read it back from the address on first load. `FinanceCalculatorPage` and `UtilityPage` wrap the calculator and show the bar; `UtilityPage` lists the shareable kinds in `SHAREABLE` (text, random and invoice tools are left out on purpose). Only numbers, dates and choices go in a link. Renaming a field label changes its key and breaks old links.
- Packs (groups of tools for one kind of person) keep everything in their own files, so a new pack never edits a big shared file:
  - config: `src/config/packs/<pack>.ts` lists the pack's tools with `definePackTool` (id, screen `kind`, `guideKey`, category, icon, tier, keywords, `shareable`); `src/config/packs/index.ts` collects the packs, and `src/config/tools.ts` appends them to `TOOLS`.
  - text: each pack has two files. `src/locales/packs/<pack>.catalog.en.json` holds `toolCatalog` (small, loaded at start; titles and descriptions in the config come from it). `src/locales/packs/<pack>.en.json` holds `guideSteps`, `pageGuides` and `toolArticles` (large, loaded on demand). `src/locales/core.ts` merges the catalogues with `en.json` (`enCore`, used by `i18n.ts`); `src/locales/content.ts` merges the heavy sections plus the depth file; `src/locales/english.ts` combines both for prerendering and types only.
  - screens: `src/components/tools/<pack>/` with a `registry.ts` of lazy screens; `src/components/tools/packRegistry.ts` merges the registries.
  - page and routes: `src/pages/PackToolPage.tsx` renders every pack tool (heading, guide, FAQ, optional share bar) and `src/App.tsx` creates one route per pack tool from the config. The static page generator and sitemap read the same config. `public/sitemap.xml` is only a fallback.
  - To add a pack: write the locale file, the config file and the screens, then add one line each in `locales/core.ts` (catalogue), `locales/content.ts` (guides and articles), `config/packs/index.ts` and `components/tools/packRegistry.ts`.
- Careers pack (`careers`): Resume Builder (`lib/careers/resume.ts`, a wording and completeness checklist, print to PDF, optional local save, data file export), Notice Period Calculator (`lib/careers/notice.ts`) and Upload File Checker (`lib/careers/fileCheck.ts`, `lib/pdf/probe.ts`).
- Students pack (`students`): GPA and CGPA Calculator (`lib/students/gpa.ts`), Final Grade Calculator (`lib/students/grades.ts`), Citation Generator (`lib/students/citation.ts`, APA, MLA, Chicago, Harvard; website, book, journal) and Study Planner (`lib/students/planner.ts`). Text is in `locales/packs/students.en.json`, tool entries in `config/packs/students.ts`, screens in `components/tools/students`.
- Freelancers pack (`freelancers`): Freelance Rate Calculator (`lib/freelancers/rate.ts`), Quotation Generator (`lib/freelancers/quote.ts`, print to PDF, optional local save of business details) and Profit Margin and Markup Calculator (`lib/freelancers/margin.ts`). Shared currency list in `lib/freelancers/currency.ts`; row editors shared in `components/tools/shared/rows.tsx`.
- `src/pages/UtilityPage.tsx` loads each calculator/utility component on demand (one `lazy()` per tool), so opening one utility does not download the others. Locale text is split: the small core (`en.json` plus tool catalogues, about 15 KB gzipped) is eager, while guide steps, FAQs and articles (about 130 KB gzipped) load as a separate chunk through `src/locales/contentLoader.ts`. `main.tsx` starts that load at once; components read it with `useContent()` (React `use`, so they suspend briefly on first load). Never import `content.ts` or `english.ts` from app code, only from prerender and tests. Other languages are hidden and have not been updated for the newer keys; they fall back to English.
- `src/pages/` connects route-specific headings and guides to tool components.
- The unlisted `/ac1` catalog trial offers designs for 4, 6, 9 or 12 products, including arched, asymmetric, side-panel and list layouts. Its English-only editor uses local sample photos, in-memory text and image edits (uploaded photos fit inside their frames by default, with per-photo zoom and vertical positioning), and browser-side PNG export for A4 and Instagram sizes. Changes are lost on reload.

## Processing and privacy

Supported file operations, calculators and text tools run in the browser; this does not mean that the entire site is offline. The site loads third-party advertising and may request PDF character maps from jsDelivr. The contact form separately sends its submitted details to Web3Forms. The privacy and terms pages describe these boundaries and must remain consistent with actual behavior. Language preferences and tool-visit counts use browser local storage. POS profiles and inventory can be explicitly saved, replaced, loaded, or deleted in IndexedDB via `src/lib/pos/profileStorage.ts`; bills and customer details are not saved there. Profile and bill JSON downloads remain the portable backup. Browser storage can be cleared or unavailable, so it is not a substitute for a backup.

Document digitization uses Tesseract.js with the English model. Vite serves and emits the worker, engine variants and language data from installed npm packages under `ocr-assets/`; they are downloaded from the application origin when needed. OCR runs on the rendered, edited pages after blackouts, and a text-only layer is added to the PDF. Separate output groups copies by source image into a ZIP. OCR is approximate and users should review the result. The digitization workspace does not offer password protection because the existing protection implementation rasterizes the PDF and removes searchable text. The reused Master Studio editor still has English-only controls.

When adding or changing a tool, keep routes, catalog entries, search, guide content, metadata, accessibility, translations, and relevant privacy disclosures consistent. Keep UI composition separate from reusable processing logic. Update this document when architecture or processing boundaries change.

Shop details (not photos or prices) are remembered in localStorage under `mdu.poster.shop.v2`. **Private `/ac1/poster`** (noindex via the `/ac1/**` header rule): same designs, but the page keeps the original `/ac1` editing style: pencil buttons over the picture edit only shop name, subheading, product names, prices, photos (change, zoom, up/down) and the three contacts. No badges, headings or other extras. `/ac1` (the chooser) lists the new designs with a product count and size choice, then the classic HTML designs, which are unchanged (`/ac1/edit`). The renderer reports where each editable element sits (`edit.hits`) so the pencils can be placed over it. **Fonts** are bundled in `src/assets/fonts/poster` (Latin subsets, SIL OFL, see LICENSES.md) and declared in `components/tools/shops/posterFonts.css`; nothing is requested from a third party. Adding a font: put the woff in that folder, add its @font-face, add the family to `POSTER_FONT_FAMILIES`. The pack also has the Price Tag Maker (`/price-tag-maker`): pasted list (`lib/shops/priceTags.ts`), A4 mm-grid sheets in three sizes printed with `window.print()`, Code 128 barcodes from `lib/barcode/code128.ts` (set B, check digit verified by decoding rendered output) or QR codes from `lib/qr`.
- Household pack (`household`): Rent Receipt Generator (`/rent-receipt-generator`). Months, Indian number-to-words and PAN shape check are in `lib/household/rent.ts`; three receipts per A4 page, printed with `window.print()`. Details can be remembered in localStorage only when the user ticks the box.
- Sports pack (`sports`): Sports Court and Ground Size Guide (`/sports-court-size-guide`). All numbers are data in `lib/sports/courtData.ts` (metres, one builder per sport, each variant lists its `sources` and clear-space `margins`; `CHECKED_ON` is the date shown on the page); lines are SVG paths from `lib/sports/shapes.ts`; `diagram.ts` draws the court to scale with its length and width, numbered key lines and the clear-space box written on it (one SVG builder used on screen and in the saved file); `annotate.ts` writes the measurements on the set-out drawing in light grey (distance of every line, rectangle edge, centre and spot from end A, end B, side A and side B, radii of circles and arcs, rectangle sizes; arcs too small to label on the line get their radius beside them); `marking.ts` reads the drawing's own SVG paths back into rectangles, lines, circles, arcs and spots (so the marking guide can never disagree with the drawing) and writes the set-out steps with exact positions from corner A and from the far end or side; `sheet.ts` lays out the saved sheet as A4 SVG pages (overview, then the set-out guide that flows over as many pages as it needs), stacks them into one tall PNG (kept under about 14 million pixels for phones) or places one page per PDF page with pdf-lib; the set-out words are under `marking` in the locale file; `fit.ts` does Fit my space (clear space per court, both orientations, courts-per-space count); `units.ts` shows metres with feet and inches. All words (names, labels, how to play, notes and risks) are in `locales/packs/sports.courts.en.json`, keyed by the ids in the data file. To add a sport: add a builder and a locale entry with every fact, mark and margin id. Known limits are in the notes: some figures come from summaries or older editions, cricket grounds are drawn as circles, football has no run-off in the Laws.
- QR pack (`qr`) also has the Bulk QR Code Generator (`/bulk-qr-code-generator`): list parsing in `lib/qr/bulk.ts` (tab, else first comma unless a link starts before it; max 500), ZIP of PNG/SVG through jszip plus `list.txt`, and a labelled print sheet.
- Privacy pack (`privacy`): Screenshot Redactor. `lib/privacy/redact.ts` (box maths, `paintRegions` for solid and pixelate, export size), screen in `components/tools/privacy`, text in `locales/packs/privacy*.en.json`, entry in `config/packs/privacy.ts`. Output is redrawn on a fresh canvas, so no layers or EXIF remain. A plain blur is deliberately not offered (can be partly reversed). No automatic text detection (would need OCR).
- Case converter: `convertCase` also does `slug` (`slugify` removes Latin accents, keeps other scripts), `constant` and `dot`.

## Extra page content (AdSense depth)

Short tool pages get extra article sections and FAQs from `src/locales/depth/core.en.json` (keys `toolArticles.<tool id>` and `pageGuides.<guide key>`). `src/locales/content.ts` inserts them before the closing privacy entry, so the original text files stay untouched. To deepen another page, add its entry to that file. Aim for 800 or more words of useful, original text per tool page (steps, article, FAQs).

## Guides

Core guides are in `src/content/guides.ts`. Guides that go with a tool pack are in `src/content/packGuides.ts` and are added to `GUIDES` there. Add the new slug to `public/sitemap.xml` too.

## Document Studio and pdf.js notes

- Document Studio text (contents titles, watermark, page-number format) is drawn by `lib/documentStudio/text.ts`: normal PDF text when the characters fit the standard font, otherwise a canvas-rendered image so Hindi, Cyrillic, Arabic, CJK and emoji export correctly. Such text is not selectable in the PDF.
- `loadPdfThumbnails` (organize) and `lib/pdf/unlock.ts` release pages, canvases and the loading task in `finally`, so errors no longer leak pdf.js memory.
